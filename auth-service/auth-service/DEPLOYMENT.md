# Инструкция по деплою эквайринга Тинькофф

## Перед деплоем на прод

### 1. Настройка переменных окружения

Убедитесь, что в продакшене установлены следующие переменные:

```bash
# Тинькофф эквайринг (получить у Тинькофф)
APP_TINKOFF_TERMINAL_KEY=ваш_терминальный_ключ
APP_TINKOFF_PASSWORD=ваш_пароль

# URL для редиректов после оплаты
APP_BILLING_SUCCESS_URL=https://ваш-домен.com/payment/success
APP_BILLING_FAIL_URL=https://ваш-домен.com/payment/fail
```

### 2. Настройка webhook в личном кабинете Тинькофф

В личном кабинете Тинькофф необходимо указать URL для уведомлений:
```
https://ваш-домен.com/billing/webhook/tinkoff
```

### 3. Проверка миграций

Убедитесь, что миграция `V6__add_cam_subscription_plans.sql` выполнена и планы CAM_1 и CAM_3 созданы в БД.

### 4. Тестирование

Перед продакшеном протестируйте:
- Создание платежной сессии через `POST /billing/create-session`
- Webhook от Тинькофф (можно использовать тестовые карты)
- Проверку создания подписки после успешного платежа

### 5. Безопасность (опционально, но рекомендуется)

В `BillingController.handleTinkoffWebhook()` есть TODO для проверки подписи webhook.
Для продакшена рекомендуется добавить валидацию `req.token` для защиты от поддельных запросов.

## Структура платежа

1. **Фронтенд получает список планов:**
   ```
   GET /billing/plans
   ```
   Ответ:
   ```json
   [
     {
       "code": "CAM_1",
       "title": "Расширение архива на 1 камеру",
       "priceMinor": 100000,
       "currency": "RUB",
       "cameraQuota": 1,
       "archiveDays": 30
     },
     {
       "code": "CAM_3",
       "title": "Расширение архива на 3 камеры",
       "priceMinor": 250000,
       "currency": "RUB",
       "cameraQuota": 3,
       "archiveDays": 30
     }
   ]
   ```

2. **Пользователь выбирает план и вызывает:**
   ```
   POST /billing/create-session
   {
     "planCode": "CAM_3"
   }
   ```
   ⚠️ **Важно:** Цена НЕ передается с фронтенда - она берется из БД по `planCode` для безопасности!

3. Система создает платеж в Тинькофф и возвращает `redirectUrl`

4. Пользователь перенаправляется на `redirectUrl` для оплаты

5. После оплаты Тинькофф отправляет webhook на `/billing/webhook/tinkoff`

6. Система автоматически создает подписку на 30 дней

## Кто тестирует?

**Бэкенд (вы):**
- ✅ Создание платежной сессии через API
- ✅ Webhook от Тинькофф
- ✅ Создание подписки после успешного платежа
- ✅ Обработка ошибок

**Фронтенд:**
- ✅ Отображение списка планов (`GET /billing/plans`)
- ✅ Вызов `POST /billing/create-session` с `planCode`
- ✅ Редирект на `redirectUrl`
- ✅ Отображение страниц success/fail после оплаты

## Логи

Все операции логируются:
- Создание платежной сессии
- Получение webhook от Тинькофф
- Создание подписки
- Ошибки обработки платежей
